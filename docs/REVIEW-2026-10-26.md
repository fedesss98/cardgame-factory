# Implementation and usability review — 2026-10-26

Verdict: the local prototype is usable for authoring and playtesting small games.
The tested flows work. This is not a production-release certification: the actual
Hostinger installation and a built Android APK/AAB need separate checks.

## Issues fixed

- Advanced JSON now belongs to the selected project. Switching projects reloads
  the correct draft, and changed source content blocks stale JSON application.
- Signing back in as the same user preserves unsaved shared working copies.
  Changing accounts clears the previous user's shared copies.
- Saving a separate shared project opens another copy instead of replacing the
  current copy's identity. Save messages clarify that concurrent edits need another save.
- Local-storage failure no longer prevents opening an in-memory workspace. Save
  status is separate from action/error messages. Starter artwork is independent of
  the previously selected game, and a failed starter-image fetch no longer blocks startup.
- Viewer controls permit browsing cards and story sections while edits remain
  disabled. The backend enforces permissions independently.
- Card search, image descriptions, keyboard focus, persistent desktop navigation
  and a scrolling playtest panel improve longer editing sessions.
- Ending artwork renders, and the restart button has readable contrast.
- Ordered effects are edited individually, preserving resource-clamping behavior.
- Validation catches missing media, duplicate membership/priorities, incorrect
  asset kinds, invalid fallback conditions and missing ending conditions.
- Referenced structure cannot be deleted; allowed deletions require confirmation.
- Export code has its own tested module. Android strings are escaped for their
  formats, Java paths follow the application ID, and exports use snapshots.
- Repeated builds replace generated player assets instead of accumulating old
  bundles. ZIP tooling loads on demand, reducing the initial editor bundle.

## Verification

- All 17 gameplay, authoring and archive tests pass on the final review run.
- TypeScript passes, including unused-local and unused-parameter checks.
- PHP syntax checks pass. The preceding review run passed all 62 HTTP integration
  checks against isolated local MariaDB 10.4.32/PHP 8.2.12: roles, CSRF/origin,
  validation, history, conflicts, revocation, password changes and throttling.
- Production editor and standalone-player builds pass.
- A separate demo was authored in the browser with three chapters, deck order and
  weights, a flag, entry effects, a transition and conditional ending with artwork.
  Its full playthrough succeeded.
- Browser checks verified card search and project-specific JSON. Desktop and
  phone-width layouts were inspected; the phone layout had no horizontal overflow.
- Backup, web and Android archives were generated with the real export template.
  The authored demo reached its expected ending using the shared engine.
- Browser download-event automation stalled. That attempt is not counted as a
  verified browser download; archive generation and contents were checked separately.

## Remaining limits

- Hostinger deployment and MariaDB 11.8.9/PHP 8.4 behavior are not verified here.
- Android compilation, signing, installation and physical-device testing are still
  pending. The output is an Android project ZIP, not a signed Play Store bundle.
- Player save/resume, undo/redo, an asset library and card deletion were added after
  this review; app-icon editing remains absent. Starter artwork is a placeholder.
  Shared saves are manual, not simultaneous editing.
- Large-project usability needs a real authoring session with dozens of cards and
  colleagues. No full accessibility audit was run.
- Some domain objects still use TypeScript `any`, and main/team components remain
  large. Rule, story, JSON and archive modules improve separation; complete domain
  typing is worthwhile before substantial expansion.
- ZIP import is intended for trusted personal backups. Expanded-size checks happen
  after decompression; untrusted archive hardening remains future work.
